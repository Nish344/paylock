Docs/API reference
Verify API
Check an answer claim by claim against the documents you supply.
POST/clocked/groundingText + images
Use Verify for grounded-answer review and RAG evaluation. It measures support in supplied sources, not truth in the outside world.
Before you send a requestAuthenticate with an account API key and provide a unique idempotency key. The fields below describe text requests. Image requests have a different response contract.
Request body#
Send a JSON object to https://clocked.rezolve.ai/clocked/grounding.
documentsarray<string | {id, text}>Conditional1–20 non-empty sources. Maximum 200,000 source characters. Sources and grounding instructions must fit the 58,000-token admission budget; serving context also applies. Required unless pdf is sent.
pdfstringA PDF, as base64 or a data:application/pdf;base64 URL, in place of documents, as the one source document, with the id pdf. It is read as text or as page images. See PDF input.
return_pdf"highlight" | "box" | "redact"Mark the answer's spans in the PDF and return the marked copy in pdf.marked.document. Text mode only. See Marking the answer back into the PDF.
answerstringRequiredThe answer to check, up to 20,000 characters.
questionstringOriginal question. Adds a separate relevance assessment: whether the answer addresses it.
claimsstring[] · 1–30Explicit claims to check. If omitted, the endpoint separates the answer into claims. Split mixed factual assertions when you need independent judgments.
instructionsstringShared reading rules or application policy. Maximum 20,000 characters. Keep source content in its source field, not in these instructions.
thresholdnumber · 0–1Default: 0.5Minimum support probability used for the grounding assessment.
evidence"all" | "flagged" | "none"Default: "flagged"Controls which findings receive source passages. Evidence may be absent when no passage is found.
rotationsinteger · 1–8Default: 3Number of option orderings to evaluate. More orderings can increase work and latency.
Claim-level results#
The overall grounded score weights support by claim length. It is not the percentage of claims that passed. A long supported sentence can outweigh a short unsupported one; inspect claims for business-critical details.
answers_question is a separate relevance signal. An answer can be grounded in a document and still fail to answer the user’s question.
claim / kind / counted / weightstring / string / boolean / numberClaim text, whether it is a factual claim, whether it contributes to the overall score, and its weight.
supported / contradicted / not_stated / not_a_claimnumber · 0–1Alternative judgments for the claim. “Not stated” means the supplied sources do not establish it; it does not mean false.
verdictstringSelected judgment for this claim.
sources / sourceobject / string | nullDocument attribution information. source can be null when no supporting source is selected.
evidence{document, quote, start, end, confidence}Optional passage. Offsets are local to the named document, not the concatenation of all documents.

}
Response body#
A successful HTTP request returns the endpoint result directly. Fields described as optional may be absent. Do not require diagnostic keys to consume a result.
modelstringModel identifier. This does not pin a deployment.
instructions_usedstringWhether default or custom instructions were used.
grounded / ungroundednumber · 0–1Aggregate support scores.
verdict / thresholdstring / numberOverall judgment and applied cutoff.
claimsarray of claim resultsIndependent judgments and available evidence.
documentsarray<{id, share, share_of_answer, claims}>Source attribution summary. claims contains indexes into the claims array.
unsupported_claims / not_claimsinteger[]Zero-based indexes into claims, when returned.
weakest_claim{index, supported} | nullLowest-support counted claim, when available.
answers_questionnumber · optionalRelevance probability when question is supplied.
pdfobject · PDF requestsThe page count, the pages read, the reading mode and, in text mode, page_offsets for finding the page of an offset. With return_pdf, marked. See PDF input.
timingobjectOptional engine timing. Keys vary by endpoint and execution path. Use HTTP response headers for gateway and billable model timing, not a fixed sum of these values.

Image input#
Use images as source documents and supply answer, plus optional question/claims. result.claims returns claim, verdict, source, and quote. Image mode has no text probability distributions or character offsets; omit threshold and rotations.
Image request and response reference Integration notes#
Evidence is optional even when requested. Do not invent a passage when one is absent.
A model can judge support incorrectly. Apply stricter review to high-impact factual claims.
